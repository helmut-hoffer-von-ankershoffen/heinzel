1"""The web app's notice stream: server-sent events under `/api`, behind the same token as every call (ADR 0041). 

2 

3`EventSource` can't send an `Authorization` header, and a token in the URL would land in the access log and the 

4browser's history, so the app reads this stream with `fetch` and the Bearer header like any other call; no ticket, 

5no cookie, nothing new to steal. CSP `connect-src 'self'` covers it. 

6 

7Every stream sends an event `changed` when the list of notices changed, for the app's list. A stream opened with 

8`?popups=true`, by a tab that may show desktop notifications, also tells the `Notifications` service every few 

9seconds that it shows them, so the daemon holds back, and sends each due notice once as an event `notice`, which the 

10app pops up and acknowledges (`POST /api/system/notify/ack`). A tab that can't pop up claims nothing, so the daemon 

11still does. A stream ends after a few minutes and the app opens a new one, so a closed tab never holds a connection 

12for long. When `hz ui` stops or restarts, every stream ends at once (`Stopping`), so the server doesn't wait for it. 

13"""
