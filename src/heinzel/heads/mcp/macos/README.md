# macOS MCP config observer

The launcher stays unavailable without a provisioned driver. The Swift managed-preference prototype is separate from the launcher. It queries only fixed vendor domains and keys through CoreFoundation and requires an App Sandbox entitlement for read-only access to exactly one domain. It reports which queried keys were forced, without copying values. Failed synchronization or a change during the sample makes the result unavailable. Two samples can detect some changes. They cannot provide an atomic view.

[Apple's domain entitlement](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/AppSandboxTemporaryExceptionEntitlements.html#//apple_ref/doc/uid/TP40011195-CH5-SW7) describes access to shared preferences in the user’s home directory. Provisioning must separately prove that the entitlement grants access to forced MDM values on each supported macOS version, and that [synchronization](https://developer.apple.com/documentation/corefoundation/cfpreferencesappsynchronize%28_%3A%29) and [forced-state lookup](https://developer.apple.com/documentation/corefoundation/cfpreferencesappvalueisforced%28_%3A_%3A%29) succeed there. A readable plist, a successful sync without a forced test value, and an empty key sample each leave managed policy unverified.

## Driver acceptance

- Codex's [macOS loader](https://github.com/openai/codex/blob/main/codex-rs/config/src/loader/macos.rs) checks `config_toml_base64` and `requirements_toml_base64` in `com.openai.codex`. Run the pinned vendor's `mcp get --json` and [`config/read`](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/json/v2/ConfigReadResponse.json) with layers for the same profile and physical workspace. Require the exact registration, executable and each argument to originate from the intended user config. A trusted workspace override, a conflicting managed layer, inaccessible policy or requirements, or a missing native result must refuse verification. The confined scratch run reached Codex's managed-preference synchronization error. A separate preference reader cannot satisfy the vendor's own sync or source checks.
- Claude Code's [managed settings](https://code.claude.com/docs/en/managed-settings) can come from remote policy and its local cache, `com.anthropic.claudecode`, managed files and drop-ins, a policy helper, or an embedding host. The MDM sample checks a subset of documented keys. Require the pinned vendor to resolve the same profile and workspace, agree with the exact user config entry, and provide sufficient policy and source evidence to rule out hidden or overriding registrations. [Managed MCP](https://code.claude.com/docs/en/mcp) can shadow or suppress user entries. `mcp get` output by itself leaves these cases unresolved. Refuse verification when a source can affect the result and the driver cannot inspect it safely.
- Cursor's [CLI list](https://cursor.com/docs/cli/mcp) reports source and transport but lacks effective executable and argument evidence. The [extension API](https://cursor.com/docs/extension-api) offers register and unregister with no matching authoritative read. Cursor stays unavailable pending a supported effective-config interface.

## Provisioning and isolated proof

1. On an authorized disposable managed Mac, build a separate, one-shot broker for each vendor. Use Hardened Runtime and App Sandbox with `com.apple.security.temporary-exception.shared-preference.read-only` containing the single vendor domain above. Verify the exact signature and entitlement set. Exclude write access, network entitlements, global Mach exceptions, debugging and loader exceptions. The broker must never run as root and must stay separate from the vendor's Seatbelt execution policy.
2. Install a test configuration profile on that Mac with a known forced value. Prove the entitled broker can detect the forced value and distinguishes an absent key from a denied lookup. Include a second domain as a denial control and cover changed policy. Keep all test values, user data and credentials out of output. Establish how the pinned vendor can resolve the applicable policy with the same account and workspace without broadening access. If its only supported operation needs unsafe privileges, the observer stays unavailable.
3. Bind both the native inspection and its applicable policy evidence to the same fresh request, package, account and physical workspace. Verify exact source, managed/project override refusal, config integrity, and denial of network, writes and unrelated execution under the production policy. Keep the parent's lifetime and output limits in effect. A preference presence sample must never produce the protocol's complete-policy success response.
4. An authorized administrator provisions the reviewed signed launcher, driver, policy, complete mapped dependency closure and stable update lock under protected ancestry. Publish the matching signed artifact hashes and package pins. Approve replacements as a new inventory under the update lock. The launcher and vendor continue to run with the user's privileges.

The [scratch fixture](../../../../../tests/fixtures/mcp/managed_preferences_test.swift) exercises the lookup contract with synthetic data and checks that the unsigned build refuses before consulting real vendor preferences. The fixture does not establish entitlements, MDM behavior, or client readiness.
