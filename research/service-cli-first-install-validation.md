# Explicit service CLI and first-install validation

This is source preparation for the next release. Published artifacts are unchanged. No OS integration, default
profile or live service was changed during this work.

Bare web-group discovery is inert. Foreground serving and opening an existing owned service have explicit commands.
Owned launchers from the published format, published updater trial arguments and inherited-socket resumes retain
compatibility without accepting modified launcher bytes. The versionless launcher uses offline command discovery
for older verified standard apps and refuses unsupported new service choices before mutation.

Interactive setup offers three independent default-yes choices. Daemon installation does not imply notifier
installation; explicit notifier consent remains separate. Every selected operation runs in the verified persistent
application. Readiness, loaded identity, persistent target and changed-installation observations gate completion;
notifier installation, permission and visible delivery remain distinct outcomes.

Profile questions use the actual profile's missing-field list and ConfigService schema and writes. They ask for
missing name and team name as requested, plus genuinely required profile fields, preserving existing values and
optional credentials. Setup completion requires an actual managed doctor result of up.

## Focused evidence

Three regression contracts fail against the original production source: inert bare web help, web installation
without a preview setting and separate interactive choices. The unchanged original source was temporarily selected
inside this worktree, all local changes were restored, and the original failures were retained in private test output.
On the new source, 494 focused CLI, profile, service ownership, session, device, updater and daemon cases passed with
two workers in 15.12 seconds. The profile-specific tests write actual configuration through the normal CLI service
boundary, preserve existing values and reject non-green setup completion.

Three real installed-wheel cases passed in 25.80 seconds: both platform-adapter session/update/cold-restart journeys
and inert installed web-group discovery with retained selected-profile refusal. These are isolated service-manager
adapters, not OS acceptance. Both Chromium and WebKit mounted phone daemon-install/removal cases passed in 10.47 seconds, retaining the actual manager hold, physical confirmation, accessibility and no-horizontal-scroll assertions. Eighteen owned Electron CLI controller tests passed. No deadline or physical interaction
was substituted; the daemon browser's named-step count now excludes the unconsented notifier step.

The initial source-environment doctor remained degraded; that observation identified default provider login and
optional alternative credentials rather than genuine profile requirements. The combined source preserves the
reviewed optional-credential commit through a normal merge. An explicit interactive Set up AI later choice now
persists supported `none` bindings while preserving existing selections and environment precedence. Its health-only
on-demand requirements never become optional execution requirements. Inventory handles authorize offline status
only; actual live-test handles are granted per operation and never cached on the inventory service.

Two further regressions fail against the committed pre-integration source in 2.41 seconds: explicitly deferred AI
was degraded, and bare noninteractive first use opened an incomplete profile. The new source passes both contracts.
A real isolated uv-tool wheel installation with a real complete profile and explicit account-free intent now has
an aggregate doctor status **up**, including genuine default notification health, in 16.90 seconds. No account,
credential, provider login, installed daemon or web server is invented to obtain that result. Installation choices
remain independent and require their actual manager/ownership proofs before onboarding can complete.

The daemon ownership/profile safety integration remains a separate required reviewed source input. Hosted CI,
real launchd/systemd installation, notification permission/delivery and complete uvx standard-composition first-use
acceptance are not verified by these fixtures. No public push, release or current live installation was changed.


The subsequent strict-type check exposed 61 bootstrap JSON-narrowing and inspection-mode comparison errors.
The bootstrap now validates managed JSON objects, configuration field identities and sources, string-only required
fields and profile enum choices at runtime, without casts or type suppressions. Malformed notifier identity and
non-boolean delivery evidence remain refusals. Focused strict Pyright, Ruff and 145 affected bootstrap/profile/module
tests pass after that repair; normal commit hooks separately retain the full mypy check. These checks do not stand
in for the pending daemon ownership ABI integration or final combined review and validation.


The final profile review found that org health's missing list does not include optional schema fields name and team.
Six real ConfigService regressions (missing or blank name/team with otherwise complete org health) fail the prior
source in 1.17 seconds. Both interactive and noninteractive onboarding now use the same strict profile-gap reader,
combining the actual missing list with required nonblank names. Duplicate field identities, missing value rows,
invalid value types and unverified field sources are refused before questions, writes, service setup or UI launch.
